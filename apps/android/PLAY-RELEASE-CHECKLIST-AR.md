# قائمة فحص نشر المدينة إكسبرس على Google Play

تحديث 2.9.9 يضيف سجلات تقنية محدودة في الخادم لتشخيص الأخطاء والأداء. حدّث إجابات أمان البيانات وسياسة الخصوصية وفق هذه السجلات وتكوين الاستضافة الفعلي؛ لم يُضف SDK تحليلات أو إعلانات. نتائج الفحوص وحدود البناء في `SECURITY-REVIEW-AR.md`.

## البناء والتوقيع

- [x] `compileSdk` و`targetSdk` مضبوطتان على API 36.
- [x] الحد الأدنى Android 7.0 (API 24).
- [x] واجهات Jetpack Compose أصلية من دون WebView.
- [x] تطبيق edge-to-edge واتجاه RTL وتصميم متكيف للشاشات الكبيرة.
- [x] عدم السماح باتصال HTTP غير المشفّر.
- [x] استبعاد الجلسة والبيانات المحلية الحساسة من النسخ الاحتياطي ونقل الجهاز.
- [x] أيقونة Adaptive مع طبقة monochrome للأيقونات ذات المظهر الموحّد.
- [ ] تشغيل Lint على نسخة 2.9.8 الحالية؛ نتائج الإصدارات السابقة لا تثبت سلامة حزمة النشر الجديدة.
- [ ] فحص حزمة النشر الحالية لمتطلبات صفحات ذاكرة 16 KiB ومراجعة المكتبات المضمنة.
- [ ] إنشاء مفتاح إصدار خاص وآمن وتفعيل Play App Signing.
- [ ] إنشاء Signed AAB بالهوية النهائية `com.almadinaexpress.app`.

## صفحة المتجر والسياسات

- [ ] نشر واختبار `https://almadina-express.onrender.com/privacy` ثم إدخاله في Play Console. الرابط متاح داخل التطبيق من شاشة الدخول والخصوصية.
- [ ] نشر واختبار `https://almadina-express.onrender.com/delete-account` لطلب الحذف دون تثبيت التطبيق، ثم إدخاله في Play Console.
- [ ] تجربة تقديم طلب الحذف داخل التطبيق أثناء وجود التزامات ومتابعة حالته وموعده؛ طلب الحذف لا يحذف فاتورة مستحقة.
- [ ] التأكد من متابعة الإدارة للطلبات خلال 7 أيام تقويمية وتوضيح إجراءات التسوية والاحتفاظ بالبيانات.
- [ ] ضبط وسيلة دعم الشركة الفعلية والتحقق من صفحة `https://almadina-express.onrender.com/support`.
- [ ] تعبئة نموذج **Data safety** بما يطابق بيانات الحساب والمستلمين والطرود والعناوين.
- [ ] تعبئة نموذج **App access** بحسابات مراجعة منفصلة للمستخدم والمندوب، وبيانات طرود وفواتير وهمية وأكواد QR تجريبية، مع شرح المسارات التي تحتاج مراجعة. لا تستخدم حسابات عملاء حقيقية أو بياناتهم.
- [ ] التصريح بأن التطبيق ليس موجّهًا للأطفال إذا كان هذا هو الاستخدام التجاري الصحيح.
- [ ] تجهيز وصف قصير وطويل، أيقونة متجر 512×512، Feature Graphic وصور هاتف/جهاز لوحي.
- [ ] التأكد من صحة بريد الدعم وموقع الشركة وبيانات المطوّر.

## الأذونات والإشعارات

- [x] طلب `POST_NOTIFICATIONS` وقت الحاجة فقط على Android 13 وما فوق.
- [x] ماسح الأكواد يستخدم Google Code Scanner ولا يطلب إذن كاميرا دائمًا.
- [x] التطبيق يعمل دون موقع الجهاز، ولا يطلب إذن موقع غير ضروري.
- [x] بصمة الإصبع والوجه اختيارية، وتظهر نافذة Android الأصلية ولا تمنع تثبيت التطبيق على جهاز بلا مستشعر.
- [ ] إنشاء مشروع Firebase وإضافة FCM إذا كانت الإشعارات الفورية أثناء إغلاق التطبيق مطلوبة.
- [ ] اختبار صوت القناة على جهاز فعلي مع إيقاف الوضع الصامت وعدم الإزعاج.

## الاختبار قبل الإنتاج

- [ ] رفع Signed AAB إلى **Internal testing** أولًا.
- [ ] اختبار حساب مستخدم ومسؤول ومندوب كل على حدة.
- [ ] اختبار تسجيل جديد، تكرار البريد/الجوال، حذف الحساب ثم إعادة إنشائه.
- [ ] اختبار إنشاء طرد وتغيير حالته والملاحظات والتحصيل والفاتورة والرواجع.
- [ ] اختبار فتح إشعار مرتبط بطرد والانتقال إلى تفاصيله.
- [ ] اختبار انقطاع الشبكة وبطء خادم Render واستعادة الاتصال.
- [ ] اختبار Android 7 وAndroid 13 وAndroid 16 وعلى هاتف وجهاز لوحي.
- [ ] اختبار تفعيل وتعطيل الدخول البيومتري على هاتف ببصمة إصبع وهاتف يدعم التعرّف على الوجه.
- [ ] مراجعة **Pre-launch report** في Play Console وإصلاح أي crash أو ANR أو مشكلة وصول.

مهم: ملف APK التجريبي موقّع بمفتاح Android Debug للاختبار فقط. لا يمكن استخدامه كنسخة إنتاج في Google Play.
