# اعتماد المستودع الموحّد على المدينة إكسبرس

التنظيم والمصدر والفحوص جاهزة داخل الحزمة. لم يتغير المستودع البعيد أو الموقع المنشور أو أي تطبيق مثبت بسبب تجهيز هذه الملفات. لا تحتاج هذه النقلة إلى تغيير عنوان API أو إنشاء قاعدة بيانات أو مسح بيانات المستخدمين.

## فتح المشاريع محليًا

1. فك ضغط الحزمة كاملة في مجلد جديد، ثم افتح `README-AR.md` من المجلد الرئيسي.
2. Android Studio: اختر **Open** ثم `apps/android`. إذا ظهر `Invalid Gradle JDK configuration`، افتح **Settings → Build, Execution, Deployment → Build Tools → Gradle** واختر JDK 17 مثبتًا وصالحًا، ثم **Sync Project with Gradle Files**.
3. Xcode: افتح `apps/ios/AlmadinaExpress.xcodeproj`، واختر حساب التوقيع وBundle Identifier المطابقين للنسخة الموجودة لديك. لا تُبدّل هوية التطبيق أثناء نقل المصدر. استخدم مشروع المجلد الجديد عند إجراء التعديلات اللاحقة.
4. الموقع: افتح `apps/web`، وثبّت اعتماداته ثم نفّذ البناء والاختبارات كما في README. بناء الموقع على Render أو في CI يستخدم Linux؛ إذا احتجت البناء على Mac فإن السكربت الحالي يتطلب GNU timeout.

ملفات الجداول المولّدة موجودة بالفعل داخل كل تطبيق. يمكن بناء كل منصة بأدواتها المعتادة دون تحميل JSON من الموقع وقت التشغيل. لا تحتاج إلى تشغيل ملف `.command` لتجميع المستودع أو فتح مشروع Xcode الجديد.

## اعتماد التنظيم في GitHub وRender

1. احتفظ بنسخة العمل الحالية وبإعدادات التوقيع والاستضافة، وأنشئ فرعًا للنقلة في المستودع المستخدم حاليًا. حافظ على سجل Git الموجود. الحزمة لا تتضمن سجل GitHub السابق.
2. اجعل بنية الفرع مطابقة للحزمة: مصدر الموقع داخل `apps/web`، وأندرويد داخل `apps/android`، والآيفون داخل `apps/ios`، والملفات المشتركة وCI في الجذر. عند نقل ملفات الموقع القديمة استخدم تتبع Git للمراجعة، وتأكد من عدم إبقاء نسخة ثانية فعّالة في الجذر. احتفظ بقيم البيئة المحلية خارج الملفات المتتبعة.
3. شغّل `python3 scripts/sync_shared.py --check` والاختبارات، ثم ارفع الفرع وراجع مقارنة الملفات. يجب أن تظهر الفحوص الرئيسية من `.github/workflows/verify.yml` في تبويب Actions. اجعل فحص `Monorepo verification` شرطًا لدمج التغييرات في الفرع الرئيسي. ملف workflow الموجود داخل مجلد Android موروث من الحزمة المستقلة؛ GitHub يشغّل workflow الجذر في التنظيم الموحّد.
4. قبل دمج نقلة المسارات، أوقف النشر التلقائي مؤقتًا **للخدمة الموجودة** في Render لتنسيق تغيير مسار المشروع. احتفظ بمعرّف الخدمة وعنوانها وربط قاعدة البيانات والمتغيرات السرية الحالية.
5. بعد نجاح الفحوص ودمج الفرع، افتح إعدادات خدمة الموقع نفسها في Render. استخدم القيم التالية، ثم انشر النسخة الجديدة من نفس الخدمة:

| الإعداد | القيمة |
|---|---|
| Root Directory | `apps/web` |
| Build Command | `npm ci --include=dev && npm run build` |
| Start Command | `npm start` |
| Health Check Path | `/health` |
| Auto-Deploy | بعد نجاح CI، أي `checksPass` في Blueprint |

عند استخدام Blueprint حالي، يكون `render.yaml` الموجود **في جذر المستودع** هو ملف التنظيم الجديد. أُبقيت أسماء الخدمة وقاعدة البيانات وتعريفات البيئة من ملف الأساس. طابق خطة الاستضافة والإعدادات مع الخدمة الفعلية قبل مزامنة Blueprint؛ الحزمة لا تستطيع معرفة التغييرات التي أُجريت في لوحة Render. إذا كنت تدير الخدمة من اللوحة، يكفي تعديل إعدادات البناء المذكورة. لا تنشئ خدمة أو قاعدة بيانات جديدة لمجرد تغيير مكان ملفات المصدر.

توضح [وثائق Render](https://render.com/docs/monorepo-support) أن أوامر البناء تُنفّذ نسبة إلى Root Directory، وأن الملفات خارج هذا المجلد غير متاحة للبناء. لهذا السبب تُحفظ مخرجات التوليد داخل `apps/web` قبل النشر. يظل JSON المشترك وأدوات التوليد في جذر المستودع للتطوير وCI. ويوثق [مرجع Blueprint](https://render.com/docs/blueprint-spec#autodeploytrigger) خيار النشر بعد نجاح الفحوص.

بعد النشر، تحقق من `/health` ومن الدخول والطرود والتحصيلات بحساب اختبار. عند الحاجة للرجوع، أعد الإصدار السابق وإعداد Root Directory الموافق لذلك الإصدار؛ الرجوع لهذه النقلة لا يتطلب تغيير قاعدة البيانات.

## إصدار التطبيقات لاحقًا

هذه النقلة لا تغيّر أرقام Android 2.9.9/41 أو iOS 1.0.12/13. التغيير في Git لا يحدّث التطبيقات المثبتة تلقائيًا. قبل رفع أي بناء جديد إلى المتجر، زِد `versionCode` في Android و`Build` في Xcode بما يتجاوز آخر بناء مرفوع، مع المحافظة على مفاتيح التوقيع وهوية التطبيق.

عند تغيير الأسعار في المستقبل، راجع توافق الخادم مع التطبيقات القديمة وخطة إصدار التطبيقات قبل النشر. ما توحّد هنا هو مصدر التعرفات؛ الخادم يظل مسؤولًا عن التحقق من العمليات والصلاحيات.
