# المدينة إكسبرس — المستودع الموحّد 1.0.0

هذا المشروع يجمع المصدر الكامل للموقع والخادم وتطبيقي Android وiOS. بُني من حزم الموقع v45، وأندرويد 2.9.9، والآيفون 1.0.12. أرقام التطبيقات نفسها محفوظة؛ 1.0.0 هنا هو إصدار حزمة المستودع، وليس إصدارًا جديدًا منشورًا في المتاجر.

| المسار | محتواه وطريقة فتحه |
|---|---|
| `apps/web` | الموقع وواجهات API؛ تُنفّذ أوامر npm من هذا المجلد. |
| `apps/android` | مشروع Android Studio؛ افتح هذا المجلد واختر Gradle JDK 17. |
| `apps/ios/AlmadinaExpress.xcodeproj` | مشروع Xcode للآيفون والآيباد. |
| `shared/pricing.json` | المصدر المشترك لرسوم التوصيل الأساسية والراجع: 3 أنواع حساب × 3 مناطق × نوعي الرسوم. |
| `scripts/sync_shared.py` | توليد الجداول داخل المشاريع الثلاثة أو التحقق من تطابقها. |
| `.github/workflows/verify.yml` | فحوص مشتركة وبناء مستقل لكل منصة متأثرة. |
| `render.yaml` | إعداد المستودع الموحّد للخدمة الحالية؛ مسار الموقع `apps/web`. |
| `release-manifest.json` | أسماء حزم الأساس وبصماتها للتتبّع. |

**التغيير الحالي يحافظ على الأسعار والواجهات وقواعد الخادم.** المقارنة مع حزم الأساس وجدت أن اختلاف ملفات تشغيل التطبيقات يقتصر على تعليقات تحديد الجداول المولّدة والمسافات. ملفات الحسابات والصلاحيات والشروط والخصوصية وواجهات المستخدم محفوظة. لا تتضمن هذه العملية اتصالًا بقاعدة بيانات الإنتاج أو ترحيلًا لها.

## ماذا تحقق من فكرة الفيديو؟

استخدام Monorepo صحيح ومناسب لجمع هذه المشاريع المترابطة. توثق [Google هذا الأسلوب وفوائده ومقايضاته](https://research.google/pubs/why-google-stores-billions-of-lines-of-code-in-a-single-repository/)، وتوثق [Uber تجربتها مع مستودع iOS المشترك](https://www.uber.com/blog/ios-monorepo/). تجربة Uber المذكورة تتعلق بمشاريع iOS، ولا تثبت أن جميع منتجات الشركة ولغاتها في مستودع واحد.

المشاركة هنا عملية: تعديل ملف التعرفات وتشغيل المولّد يحدّث مصادر TypeScript وKotlin وSwift في تغيير واحد يمكن مراجعته. لكل منصة واجهتها وأدوات بنائها. يستلزم وصول تعديل لاحق إلى المستخدمين نشر الموقع وبناء وإصدار تحديثات التطبيقات المناسبة. تنظيم المستودع وحده لا يغيّر سرعة التطبيق أو سعة الخادم أو مستوى الحماية أثناء التشغيل.

## العمل من المجلد الرئيسي

يلزم Python 3.10 أو أحدث للأدوات المشتركة. شغّل من المجلد الذي يحتوي هذا الملف:

```bash
python3 scripts/sync_shared.py --check
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

عند اعتماد تعديل حقيقي على رسوم التوصيل أو الراجع، عدّل `shared/pricing.json` ثم شغّل:

```bash
python3 scripts/sync_shared.py
python3 scripts/sync_shared.py --check
```

احفظ الملف المشترك والمخرجات الثلاثة معًا في نفس Git commit. يفشل فحص CI إذا نُسي توليد أي منصة. يعمل المولّد على الجداول المحددة وتعرفة المحافظات القياسية في الموقع؛ قواعد الوزن والحجم والتحقق والصلاحيات تبقى في ملفاتها الحالية. حالات الأسعار المتوقعة في الاختبارات مستقلة عن المولّد؛ يجب مراجعتها عند إقرار تغيير تجاري في الأسعار.

## التحقق والبناء

الموقع يحتاج نسخة Node المحددة في `apps/web/.node-version`. من `apps/web`:

```bash
npm ci --include=dev
npm test
```

ومن جذر المستودع، اختبار توافق التعرفات مع وظائف الموقع الفعلية:

```bash
node --experimental-strip-types --test tests/pricing-contract.test.mjs
```

من `apps/android`، مع JDK 17 وAndroid SDK 36:

```bash
bash gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

من `apps/ios` على Mac مع Xcode 26 ومحاكيات iPhone وiPad مثبتة:

```bash
bash scripts/verify-mac.sh
```

فحوص GitHub تعمل بعد رفع المستودع. تعديل منصة منفردة يبني تلك المنصة؛ تعديل الملفات المشتركة أو أدوات التوليد أو CI يبني المنصات الثلاث. يمر الاختبار النهائي `Monorepo verification` فقط عند نجاح جميع المنصات المطلوبة. شغّل `workflow_dispatch` لفرض بناء الجميع. الوظائف لا تملك صلاحية كتابة المستودع ولا تنشر الموقع أو التطبيقات في المتاجر.

نتائج هذه الحزمة وحدودها موثقة في `docs/VERIFICATION-AR.md`. للاعتماد على الخدمة الموجودة وفتح النسخ الصحيحة اتبع `docs/MIGRATION-AR.md`.
