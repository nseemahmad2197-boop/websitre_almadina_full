# المدينة إكسبرس | Almadina Express

مشروع موقع عربي كامل لإدارة الشحن والتوصيل داخل فلسطين. صُمم استنادًا إلى الفيديوهات المرجعية، ويعمل على الهاتف والكمبيوتر مع واجهة عربية من اليمين إلى اليسار.

## تشغيل المشروع في VS Code

1. ثبّت **Node.js الإصدار 22 أو أحدث** من: https://nodejs.org/
2. فك ضغط المشروع في مجلد عادي؛ لا تشغّله وهو داخل الملف المضغوط.
3. افتح المجلد الكامل في VS Code باستخدام **File → Open Folder**.
4. افتح الطرفية باستخدام **Terminal → New Terminal**.
5. نفّذ الأمر التالي مرة واحدة لتثبيت المكتبات:

   ```bash
   npm install
   ```

6. بعد انتهاء التثبيت، شغّل الموقع:

   ```bash
   npm run dev
   ```

7. افتح الرابط الذي يظهر في الطرفية، وغالبًا يكون:

   ```text
   http://localhost:5173
   ```

يمكن كذلك تشغيل `RUN-WINDOWS.bat` على Windows أو `RUN-MAC.command` على macOS. هذه الملفات تثبّت المكتبات تلقائيًا عند التشغيل للمرة الأولى.

> لا يحتاج التشغيل المحلي الأساسي إلى Supabase أو Firebase. إنشاء حساب جديد وإعادة تعيين كلمة المرور يرسلان رمز تحقق فعليًا بالبريد الإلكتروني، ولذلك يحتاجان إعداد Brevo كما هو موضح أدناه.

## الرفع من VS Code إلى GitHub ثم Render

المشروع جاهز للنشر على Render من خلال الملف `render.yaml`. ينشئ هذا الملف خدمة الموقع وقاعدة PostgreSQL ويربطهما تلقائيًا، لذلك لا تكتب `DATABASE_URL` يدويًا ولا ترفعه إلى GitHub.

### 1. رفع المشروع إلى GitHub

1. أنشئ مستودعًا جديدًا وفارغًا في [GitHub](https://github.com/new) ولا تضف README أو `.gitignore` من GitHub.
2. انسخ رابط المستودع الذي ينتهي بـ `.git`.
3. افتح مجلد المشروع الكامل في VS Code، ثم افتح **Terminal → New Terminal** ونفّذ:

   ```bash
   git init
   git add .
   git commit -m "Deploy Almadina Express"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPOSITORY.git
   git push -u origin main
   ```

4. استبدل `USERNAME/REPOSITORY` باسم حسابك ومستودعك. إذا ظهر أن `origin` موجود مسبقًا، نفّذ بدل أمر الإضافة:

   ```bash
   git remote set-url origin https://github.com/USERNAME/REPOSITORY.git
   git push -u origin main
   ```

قد يفتح GitHub نافذة المتصفح لتسجيل الدخول عند أول `push`. لا تضع كلمة مرور GitHub أو أي مفتاح داخل ملفات المشروع.

### 2. نشر المستودع على Render

1. سجّل الدخول إلى [Render](https://dashboard.render.com/) بواسطة GitHub.
2. اختر **New + → Blueprint** ثم اربط مستودع المشروع.
3. سيتعرّف Render تلقائيًا على `render.yaml` ويعرض خدمتين: `almadina-express` و`almadina-express-db`.
4. اضغط **Apply** وانتظر حتى تنتهي حالة النشر إلى **Live**.
5. افتح رابط `onrender.com` الذي يظهر في صفحة خدمة `almadina-express`.

بعد أي تعديل لاحق من VS Code استخدم:

```bash
git add -A
git commit -m "Update website"
git push
```

سيبدأ Render نشر النسخة الجديدة تلقائيًا بعد وصول التعديل إلى فرع `main`.

> عند تحديث موقع منشور بالفعل، ارفع الملفات إلى **المستودع نفسه والفرع `main` نفسه** واترك خدمة Render وقاعدة PostgreSQL الحالية كما هما. لا تنشئ Blueprint أو قاعدة بيانات جديدة، ولا تحذف خدمة قاعدة البيانات؛ نشر الكود الجديد لا يمسح الحسابات أو الطرود الموجودة.

> إعداد Render المرفق يستخدم الخطة المجانية للتجربة. خدمة الويب المجانية قد تتوقف مؤقتًا عند عدم الاستخدام، وقاعدة PostgreSQL المجانية تنتهي بعد 30 يومًا. للحفاظ على الحسابات والطرود بصورة دائمة، رقِّ قاعدة البيانات إلى خطة مدفوعة قبل انتهاء المدة؛ لا يحتاج الموقع إلى تعديل برمجي عند الترقية.

## إعداد إرسال رموز إعادة تعيين كلمة المرور

تعمل استعادة كلمة المرور عبر **البريد الإلكتروني المسجّل في حساب المستخدم فقط**. عندما يطلب المستخدم الاستعادة، يبحث الخادم عن الحساب ثم يرسل رمزًا من 6 أرقام عبر **Brevo** إلى البريد المحفوظ في ذلك الحساب. لا يوجد إرسال أو تحقق عبر رقم الهاتف.

| المتغير | الاستخدام |
| --- | --- |
| `BREVO_API_KEY` | مفتاح API السري من **Brevo → SMTP & API → API Keys** لإرسال رموز التسجيل وإعادة تعيين كلمة المرور. |
| `BREVO_FROM_EMAIL` | بريد المرسل الذي أضفته وفعّلته في **Brevo → Senders, Domains & Dedicated IPs → Senders**. تصل الرسالة إلى بريد المستخدم الذي أدخله. |
| `BREVO_FROM_NAME` | اسم المرسل الظاهر للمستخدم. يضبطه `render.yaml` تلقائيًا على `Almadina Express`. |

لا تضع مفتاح Brevo أو أي قيمة سرية داخل `README.md` أو ملفات المصدر أو GitHub، ولا تستخدم البادئتين `VITE_` أو `NEXT_PUBLIC_` لهذه القيم لأنهما مخصصتان للبيانات التي قد تصل إلى المتصفح.

قبل الاعتماد على الاستعادة في الإنتاج، تأكد أن لكل مستخدم بريدًا صحيحًا يمكنه الوصول إليه. لن يرسل الخادم الرمز إلى عنوان مختلف يختاره الزائر؛ بل يطابق البريد المدخل مع الحساب ثم يرسل إلى البريد المحفوظ فيه فقط.

### Render

يعلن `render.yaml` متغيري `BREVO_API_KEY` و`BREVO_FROM_EMAIL` مع `sync: false`، ولذلك لا يحفظ قيمهما في المستودع. عند إنشاء Blueprint لأول مرة سيطلب Render القيمتين. ولخدمة منشورة مسبقًا افتح خدمة `almadina-express` ثم **Environment** وأضف:

```text
BREVO_API_KEY = مفتاح Brevo السري
BREVO_FROM_EMAIL = بريد المرسل المفعّل في Brevo
```

المتغير `BREVO_FROM_NAME` موجود تلقائيًا في Blueprint. احفظ التغييرات ثم اختر إعادة النشر. يبقى `DATABASE_URL` مرتبطًا بقاعدة البيانات تلقائيًا ولا يحتاج إدخالًا يدويًا.

### Cloudflare Workers/Sites

أضف `BREVO_API_KEY` كسر مشفّر، وأضف `BREVO_FROM_EMAIL` و`BREVO_FROM_NAME` كمتغيرات تشغيل أو أسرار. تصل القيم إلى التطبيق من bindings الخاصة بالـ Worker؛ لا تضفها إلى `.openai/hosting.json` ولا إلى ملفات المصدر.

### التشغيل المحلي

للتجربة بإرسال حقيقي، أنشئ ملفًا باسم `.env.local` في جذر المشروع واملأ القيم على جهازك فقط:

```dotenv
BREVO_API_KEY=
BREVO_FROM_EMAIL=
BREVO_FROM_NAME=Almadina Express
```

يمكن استخدام `.dev.vars` بدلًا منه مع تشغيل Cloudflare المحلي. كلا النمطين مستبعد من Git، فلا تستخدم خيار الإضافة الإجبارية لهما ولا تنسخ محتواهما إلى سجل الطرفية أو لقطات الشاشة. يستطيع الموقع العمل دون هذه القيم، لكن إرسال رموز إعادة التعيين لن يكون متاحًا حتى تكتمل بيانات Brevo.

## إعداد قراءة العنوان من دبوس الخريطة

تعرض خطوة العنوان مسارين واضحين: **إدخال يدوي** و**تحديد بالخريطة** عبر خريطة تفاعلية من OpenStreetMap. في الإدخال اليدوي يكفي اختيار/كتابة المدينة والمنطقة والشارع، ولا يطلب الموقع إذن الجهاز أو تثبيت دبوس. وفي مسار الخريطة يرسل الخادم إحداثيات الدبوس بعد ضغط «تثبيت وقراءة العنوان» ويملأ أفضل مدينة ومنطقة وشارع تعيدها **Geoapify**، مع بقاء النص قابلًا للتصحيح يدويًا.

زر «موقعي» يجرب أولًا تحديدًا سريعًا ومتوازنًا ثم يعيد المحاولة بدقة أعلى إذا تعذر تحديد الموقع. يتطلب تحديد موقع الجهاز رابط HTTPS (وهو متوفر تلقائيًا على Render)، والسماح للموقع في المتصفح، وتشغيل **خدمات الموقع** على نظام الهاتف أو الكمبيوتر. تعطل GPS لا يمنع التسجيل؛ اختر «إدخال يدوي» وأكمل العنوان مباشرة.

1. أنشئ مشروعًا في Geoapify وانسخ مفتاح API الخاص به.
2. في Render افتح خدمة `almadina-express` ثم **Environment** وأضف السر التالي واحفظ التغييرات وأعد النشر:

```text
GEOAPIFY_API_KEY = مفتاح Geoapify السري
```

يعلن `render.yaml` هذا المتغير مع `sync: false` ولا يحفظ قيمته في GitHub. يطلب Render قيمته عند **إنشاء Blueprint لأول مرة فقط**؛ أما Blueprint المنشور مسبقًا فيتجاهل متغيرات `sync: false` الجديدة عند المزامنة. أضف `GEOAPIFY_API_KEY` يدويًا إلى Environment الخاصة بخدمة `almadina-express`، أو إلى **Environment Group مرتبط بهذه الخدمة**، ثم احفظ وأعد النشر. في Cloudflare أضفه كسر مشفّر بالاسم نفسه. وللتشغيل المحلي أضفه إلى `.env.local` أو `.dev.vars`:

```dotenv
GEOAPIFY_API_KEY=
```

لا تضع المفتاح في ملفات المصدر، ولا تسمّه `VITE_GEOAPIFY_API_KEY` أو `NEXT_PUBLIC_GEOAPIFY_API_KEY`. يستدعي المتصفح مسار الموقع الداخلي فقط، ويتولى الخادم الاتصال بخدمة Geoapify حتى لا ينكشف المفتاح للمستخدمين.

## إعداد حساب المسؤول بأمان

لم يعد المشروع يحتوي على كلمة مرور مسؤول ثابتة أو منشورة. **أضف القيم التالية في Render قبل نشر هذه النسخة**، إما في Environment الخاصة بخدمة `almadina-express` أو داخل Environment Group مرتبط بها:

```text
ALMADINA_ADMIN_PASSWORD = كلمة فريدة من 12 محرفًا على الأقل، وبها حرف ورقم ورمز
ALMADINA_ADMIN_EMAIL = بريد المسؤول الصحيح
ALMADINA_ADMIN_PHONE = رقم من 10 أرقام يبدأ بـ 05
```

المتغير `ALMADINA_ADMIN_NAME` مضبوط في Blueprint على `إدارة المدينة إكسبرس` ويمكن تغييره. لا تضع كلمة المرور أو القيم الحقيقية في GitHub أو README أو لقطة شاشة. عند أول تشغيل ينشئ الخادم المسؤول من هذه الأسرار. وعند تغيير بريد أو كلمة مرور المسؤول داخل Environment Group ثم إعادة تشغيل الخدمة، يزامن الخادم حساب المسؤول الأساسي مع القيم الجديدة ويلغي جلساته القديمة فقط عند تغيّر بيانات الدخول. وإذا كانت قاعدة البيانات قد تهيأت بالفعل قبل وصول القيم الجديدة، يستطيع مسار تسجيل الدخول نفسه إعادة مزامنة الحساب بأمان بعد إدخال البريد وكلمة المرور المطابقين تمامًا لأسرار Render؛ ولا يُسمح لطلب لا يملك كلمة المرور الصحيحة بتشغيل عملية المزامنة. تعالج المزامنة أيضًا قواعد البيانات القديمة التي خزّنت كلمة المرور بصيغة قديمة، من دون حذف المستخدمين أو الطرود أو الفواتير. لذلك اجعل قيم Render هي المرجع الدائم لحساب المسؤول الأساسي، وإذا غيّرت كلمة مروره من داخل الموقع فحدّث `ALMADINA_ADMIN_PASSWORD` في Render أيضًا قبل إعادة تشغيل الخدمة.

لإضافة حساب مسؤول شخصي ثانٍ **من دون استبدال حساب المسؤول الأساسي**، أضف المتغيرات التالية إلى Environment Group المرتبط بالخدمة. يجب أن يكون البريد مختلفًا عن أي حساب مسجّل حاليًا، وأن يكون رقم الهاتف من 10 أرقام ويبدأ بـ `05`:

```text
ALMADINA_SECOND_ADMIN_EMAIL = بريد المسؤول الثاني
ALMADINA_SECOND_ADMIN_PASSWORD = كلمة فريدة من 12 محرفًا على الأقل، وبها حرف ورقم ورمز
ALMADINA_SECOND_ADMIN_PHONE = رقم هاتف المسؤول الثاني
ALMADINA_SECOND_ADMIN_NAME = اسم المسؤول الثاني
```

عند إعادة تشغيل الخدمة ينشئ الخادم الحساب الثاني أو يزامنه مع هذه القيم، بينما يبقي حساب `ALMADINA_ADMIN_*` وجميع بيانات الموقع كما هي. لا تستخدم البريد نفسه للحسابين، ولا تحفظ أيًا من القيم السرية في GitHub. إذا أزلت متغيرات الحساب الثاني لاحقًا فلن يحذف الخادم الحساب أو بياناته تلقائيًا.

لا يحتوي المشروع على مستخدمين أو طرود أو مستلمين تجريبيين. أنشئ حساب عميل جديد من شاشة التسجيل، أو أضف المستخدمين والمندوبين يدويًا من لوحة المسؤول. يجب أن يكون رقم الجوال الفلسطيني مكوّنًا من 10 أرقام ويبدأ بـ `05`.

كل مستخدم يشاهد حسابه وطروده ومستلميه وفواتير تحصيله وإشعاراته فقط. لتبديل الحساب يجب تسجيل الخروج، ثم استخدام البريد وكلمة المرور أو حماية الجهاز إذا سبق تفعيلها. يحتفظ المسؤول بصلاحية إدارة جميع المستخدمين والطلبات، ويُعامل كل حساب «مندوب توصيل» ينشئه المسؤول كحساب موظف بصلاحيات تشغيلية مستقلة.

## الصفحات والخصائص

- تسجيل الدخول، وإنشاء حساب جديد عبر خمس خطوات واضحة (البيانات الأساسية، المتجر والبريد، العنوان والخريطة، حماية الحساب، المراجعة) ثم رمز من 6 أرقام يُرسل إلى بريد المستخدم عبر Brevo. لا يُنشأ الحساب ولا تبدأ الجلسة قبل نجاح التحقق. ويظهر زر للحسابات المتاحة التي سبق استخدامها على الجهاز في الشاشات الصغيرة فقط، مع زر مستقل لإزالة كل حساب من قائمة الجهاز دون حذف الحساب الحقيقي أو بياناته، وتبديل الحسابات بكلمة المرور أو ببصمة الوجه/حماية الجهاز المفعّلة، وتتبع الطرود دون تسجيل الدخول بسجل زمني آمن. يعمل الدخول بحماية الجهاز للحساب العادي والبريميوم والماسي والموظف والمسؤول بعد تفعيل قفل التطبيق وربط الحماية بإدخال رمز القفل.
- تعرض خطوة المراجعة زرًا واضحًا لفتح شروط الاستخدام وسياسة الخصوصية والأذونات وخصائص الجهاز المستخدمة. يجب تمرير المحتوى كاملًا من أعلاه إلى نهايته قبل تفعيل خانة الموافقة. توضّح الصفحة استخدام الكاميرا والموقع والرسائل القصيرة للمندوب وحماية الجهاز والتخزين والصوت، وتؤكد في نهايتها أن الطرد يجب أن يكون مطابقًا للوصف المكتوب. تبقى الوثائق نفسها متاحة لاحقًا من الإعدادات.
- تتضمن خطوة «العنوان الخاص بك» اختيارًا مستقلًا بين الإدخال اليدوي والتحديد بالخريطة. الإدخال اليدوي لا يفرض دبوسًا أو إذن موقع. وعند اختيار الخريطة يستطيع المستخدم تحريكها أو طلب موقع الجهاز، ثم يقرأ الخادم المدينة والمنطقة والشارع عبر Geoapify ويدعم أشكال الاستجابة المختلفة للخدمة. تُحفظ إحداثيات النقطة فقط عند اختيار الخريطة وبعد نجاح تحقق البريد؛ وتحتاج التعبئة التلقائية إلى `GEOAPIFY_API_KEY` على الخادم.
- زر «نسيت كلمة المرور؟» يرسل رمز التحقق عبر Brevo إلى البريد الإلكتروني المسجّل فقط، ثم يتيح إدخال الرمز وتعيين كلمة مرور جديدة دون كشف ما إذا كان حساب غير معروف موجودًا أم لا.
- حسابات وطلبات محفوظة في قاعدة بيانات مشتركة، مع إمكانية تسجيل الدخول إلى الحساب نفسه من أي جهاز يفتح رابط الموقع نفسه.
- ماسح كاميرا لرموز QR والباركود في المتصفحات التي تدعم `BarcodeDetector`، مع إدخال رقم التتبع يدويًا.
- واجهة موظف مستقلة لحسابات المندوبين: يمسح الموظف كود الطرد بالكاميرا، ولا يقبل الخادم إلا نقل الحالة من «جاهز للإرسال» إلى «مشحون». كما يستطيع إدخال كود تحقق فاتورة تحصيل جاهزة لتصبح «تم التسليم»، مع حفظ اسمه ووقت التحقق وإشعار صاحب الفاتورة.
- يعرض حساب الموظف الطرود التي استلمها فقط وتعليمات المندوب المكتوبة عند إنشاء الطرد، ويعرض من فاتورة التحصيل الجاهزة رقمها واسم صاحبها وحالتها فقط دون كشف رمز التحقق أو المبالغ أو الرسوم أو أعداد الطرود أو تفاصيلها أو الملاحظة الخاصة بالمسؤول. ولا يستطيع حساب المستخدم العادي استدعاء صلاحيات الموظف.
- لوحة العميل وإحصاءات الرصيد وحالات الطرود والتحديثات.
- إنشاء طرد، اختيار المحافظة والمدينة من دليل ثابت يضم 524 تجمعًا رسميًا في الضفة والقدس و1,120 اسم منطقة فريدًا للداخل، وكتابة الحي والشارع في حقل وصف العنوان، واحتساب رسوم التوصيل تلقائيًا، وحفظ المحافظة مع المستلم المفضل لمنع التباس الأسماء المتكررة أو التلاعب بالتسعير. يبدأ كل طرد جديد بحالة «قيد الإنشاء» ثم تُفتح رحلة تتبعه مباشرة. تظهر «التعليمات» للمندوب المسند فقط، بينما تظهر «الملاحظة الخاصة» للمسؤول فقط.
- سجل تتبع دائم من الأحدث إلى الأقدم يوضح وقت كل تحديث وموقعه وحالته وملاحظته، ويضيف حدثًا جديدًا عند تغيير الحالة بدل حذف السجل السابق.
- ملاحظات مرتبطة بحالات الطرد: يستطيع المستخدم صاحب الطرد والمسؤول إضافة ملاحظة للحالة الحالية، ويستطيع المسؤول كتابة ملاحظة اختيارية عند اعتماد أي حالة جديدة؛ يُحفظ اسم الكاتب والوقت ولا تظهر الملاحظات الخاصة في التتبع العام دون تسجيل.
- الطرود والرواجع والتحصيلات والإشعارات والبحث والمحذوفات.
- تنزيل تقارير CSV وExcel، واستيراد عدة طرود باستخدام ملف CSV قابل للفتح في Excel. يستخدم النموذج الجديد عمودين منفصلين للمحافظة والمدينة حتى تُحفظ المناطق المتشابهة بالاسم بصورة صحيحة، مع استمرار دعم النموذج القديم عندما يكون اسم المنطقة غير ملتبس.
- صفحة تحصيلات تعرض المبالغ المتاحة وقيد التجهيز والجاهزة والمسلّمة، وتنشئ فواتير من الطرود الواصلة والرواجع دون تكرارها.
- تفاصيل لكل فاتورة تشمل صافي التحصيل، رسوم التوصيل، توزيع الطرود حسب المنطقة، الاستثناءات، التنزيل والطباعة، ورمز تحقق لمستلم مفوض.
- لوحة إدارة للتجار والمندوبين والطرود والتحصيلات، تغيير حالات الطرود، تجهيز فواتير التحصيل، وإضافة حسابات الموظفين/المندوبين وحذفها.

## الحماية والأمان

- كل صلاحية حساسة تُراجع على الخادم باستخدام جلسة `HttpOnly` و`SameSite=Strict`؛ إخفاء الزر في الواجهة ليس هو وسيلة الحماية.
- لا يستطيع التاجر تغيير حالة الطرد أو رسوم التوصيل أو رقم التتبع أو هوية المالك من أدوات المطور؛ يعيد الخادم احتساب الرسوم ويحتفظ بالقيم التشغيلية الموثوقة.
- استجابة التتبع العامة لا تعرض اسم المستلم أو هاتفه أو عنوانه أو الملاحظات الداخلية، وتوجد حدود لمحاولات التتبع وتسجيل الدخول وأكواد التحقق.
- يرفض الخادم الطلبات ذات المصدر أو نوع المحتوى أو الحجم غير المسموح، وتضيف طبقة التشغيل ترويسات تمنع تضمين الموقع داخل إطار وتقيّد أذونات الكاميرا والموقع إلى الموقع نفسه.
- لا تُخزن كلمات المرور أو رموز التسجيل وإعادة التعيين بصورتها النصية؛ وتبقى مفاتيح Brevo وGeoapify وأسرار المسؤول في Render فقط.
- تعالج عملية تصدير CSV القيم التي قد يفسرها Excel كصيغة تنفيذية. أظهر فحص `npm audit` صفر ثغرات معروفة في شجرة الحزم وقت تجهيز هذه النسخة.

أدوات المطور تعرض ملفات JavaScript التي تصل إلى المتصفح في أي موقع ويب، ولا يمكن منع ذلك تقنيًا. الحماية الصحيحة هي عدم إرسال الأسرار والبيانات غير المصرح بها إلى المتصفح، وعدم الثقة بأي قيمة يعدلها المستخدم محليًا؛ وهذا هو الأسلوب المستخدم هنا. لا يوجد نظام يمكن ضمان أنه «غير قابل للاختراق» نهائيًا، لذلك يجب إبقاء الحزم محدثة ومراجعة سجلات Render والنسخ الاحتياطية دوريًا.
- بيانات الاسم والجوال والمتجر أو المنطقة والبريد للعرض فقط داخل حساب المستخدم والمندوب؛ تعديلها متاح للمسؤول وحده من لوحة الإدارة، ومحمِي كذلك من جهة الخادم.
- تغيير نوع حساب التاجر يدويًا بين «عادي» و«بريميوم» و«ماسي» من تبويب المستخدمين في لوحة المسؤول.
- أسعار التوصيل للحساب العادي: جميع مناطق الضفة 25 شيكل، القدس 35 شيكل، والداخل 80 شيكل.
- أسعار التوصيل لحساب بريميوم: جميع مناطق الضفة 20 شيكل، القدس 30 شيكل، والداخل 65 شيكل؛ تُطبّق تلقائيًا على إنشاء الطرود واستيرادها بعد تغيير نوع الحساب من لوحة المسؤول.
- أسعار التوصيل للحساب الماسي: جميع مناطق الضفة 15 شيكل، القدس 25 شيكل، والداخل 55 شيكل؛ تُطبّق تلقائيًا على الطرود الجديدة والاستيراد، ولا تعيد تسعير الطرود القديمة.
- رسوم الرواجع للحساب العادي: الضفة الغربية 20 شيكل، القدس 30 شيكل، والداخل 50 شيكل. ولحساب بريميوم: الضفة 15، القدس 25، والداخل 40 شيكل. وللحساب الماسي: الضفة 10، القدس 15، والداخل 25 شيكل. يحتسب الخادم هذه الرسوم عند إنشاء فاتورة التحصيل ويعيد التحقق منها عند تجهيز الفاتورة وتسليمها، ويرقّي الفواتير القديمة تلقائيًا من التعرفة السابقة. تحفظ كل فاتورة تفصيل رسم كل طرد راجع حتى يتطابق المبلغ في البطاقة والملخص والتفاصيل لدى المستخدم والمسؤول.
- تبدأ رسوم الحجم من 7 شيكل عندما يتجاوز أكبر بُعد 40 سم، وتزداد 7 شيكل لكل 20 سم إضافية حتى حد أقصى 28 شيكل؛ كما تزداد رسوم الوزن تدريجيًا حسب الفئة المختارة. لا تُضاف رسوم حجم عند 40 سم بالضبط، وتشمل الحسابات إنشاء الطرد والاستيراد وفواتير التحصيل.
- يعمل صوت الإشعار للحسابات العادية والبريميوم والماسية وللموظف والمندوب والمسؤول. تُصدر الإشعارات غير المقروءة صوتًا أيضًا بعد تبديل الحساب أو الرجوع إلى الصفحة، ويؤجَّل الصوت إلى أول لمسة آمنة إذا أوقف المتصفح تشغيل الصوت أثناء وجود الصفحة في الخلفية.
- الإعدادات، الملف الشخصي، وتغيير كلمة المرور بعد التحقق من الكلمة الحالية. تعرض صفحة «الأجهزة المرتبطة» عدد جلسات الدخول النشطة وأسماء تقريبية مثل «Safari على iPhone» وآخر نشاط، مع تسجيل خروج جهاز آخر دون حذف الحساب أو الطرود أو التحصيلات. ويمكن للمستخدم كذلك إبقاء جلساته عند تغيير كلمة المرور أو تسجيل الخروج من جميع الأجهزة وإبطال البصمة القديمة حتى يعيد ربطها.
- رمز قفل محلي، تفضيلات الإشعارات، الوضع الفاتح والداكن، مركز المساعدة، وصفحة موحدة لشروط الاستخدام وسياسة الخصوصية والأذونات المستخدمة.
- تصميم متجاوب لجميع الشاشات، انتقالات، قوائم جانبية، تفاصيل فواتير ورمز تحقق متكيفان، وشريط تنقل سفلي للجوال والكمبيوتر.
- استيراد Excel من الشريط العلوي في نسخة الكمبيوتر فقط، دون ظهوره في قائمة الهاتف الجانبية.
- طباعة ملصقات جميع طرود المستخدم دفعة واحدة من شاشة الطرود على الشاشات الكبيرة فقط، مع تخصيص صفحة طباعة لكل طرد.

## حفظ البيانات

تُحفظ الحسابات والطلبات والمستلمون وفواتير التحصيل والإعدادات في قاعدة بيانات مشتركة على الخادم: **Cloudflare D1** في تشغيل Cloudflare أو **PostgreSQL** عند النشر على Render. يحفظ الحساب الجديد كذلك المدينة والمنطقة والشارع وإحداثيات نقطة الخريطة التي ثبّتها المستخدم، وتظهر بيانات العنوان للقراءة داخل ملفه الشخصي. لا تُحفظ كلمات المرور أو بيانات الطرود في `localStorage`؛ تُحفظ فقط بيانات تعريف غير حساسة للحسابات التي سبق استخدامها على الجهاز لتكوين قائمة «الحسابات المتاحة». تُشفّر كلمات المرور باستخدام PBKDF2، وحتى طلب التسجيل المؤقت يحفظ كلمة المرور والرمز كقيم مشفّرة/مشتقة لا كنص واضح، ثم يُحذف بعد نجاح التحقق أو انتهاء الصلاحية. تُحفظ جلسات تسجيل الدخول في ملفات تعريف ارتباط `HttpOnly` منفصلة لكل جهاز. يحفظ جدول مستقل اسمًا تقريبيًا آمنًا للجهاز ونوع المتصفح وآخر نشاط فقط، ولا يحفظ عنوان IP أو نص User-Agent الخام. يحسب الخادم قيمة كل فاتورة من الطرود الفعلية ويحمي حالتها وأرقامها من التعديل في المتصفح، ويتحقق من كود التحصيل وصلاحية الموظف على الخادم قبل اعتماد حالة «تم التسليم». وتُعامل الفواتير القديمة المحفوظة بحالة «مشحون» تلقائيًا كفواتير مسلّمة ومكتملة حتى لا تمنع حذف الحساب بعد اكتمال الطرود.

حماية الجهاز مبنية على WebAuthn؛ لذلك قد يعرض الهاتف Face ID أو بصمة الإصبع أو رمز حماية الجهاز وفق نظام التشغيل. الحسابات التي ربطت البصمة قبل إضافة الدخول بعد تسجيل الخروج تحتاج مرة واحدة فقط إلى إيقاف خيار البصمة ثم تفعيله مجددًا من الإعدادات كي يُنشأ مفتاح الدخول القابل للاستخدام من شاشة تسجيل الدخول.

دليل المناطق يولَّد مسبقًا بواسطة `scripts/generate-palestine-locations.py` من جداول التجمعات التابعة للجهاز المركزي للإحصاء الفلسطيني ومن مصدري أسماء المواقع والمناطق في بوابة البيانات الحكومية، ثم يُحفظ ثابتًا داخل المشروع؛ لا يتصل الموقع بهذه المصادر أثناء التشغيل.

يمكن إنشاء الحساب من الهاتف ثم فتح رابط الموقع نفسه من الكمبيوتر أو أي هاتف آخر وتسجيل الدخول بالبريد الإلكتروني وكلمة المرور نفسيهما. تتم مزامنة الطلبات وتغييرات الحساب تلقائيًا بين الأجهزة، ويشاهد كل مستخدم بياناته الخاصة فقط، بينما يشاهد المسؤول جميع الحسابات والطلبات.

عند تشغيل `npm run dev` تُحفظ قاعدة البيانات المحلية داخل مجلد `.wrangler` على جهاز تشغيل الخادم. لفتح الموقع من هاتف آخر على شبكة Wi‑Fi نفسها استخدم عنوان **Network** الظاهر في الطرفية، مع إبقاء الخادم يعمل. للوصول من أي مكان خارج الشبكة المحلية، انشر الموقع على Render وفق الخطوات أعلاه أو على Cloudflare Workers/Sites؛ لا يكفي فتح `localhost` على كل جهاز على حدة.

تعريف قاعدة البيانات موجود في `.openai/hosting.json` تحت `"d1": "DB"`، وملفات إنشاء الجداول موجودة داخل مجلد `drizzle`.

## الملفات المهمة

- `app/page.tsx`: نقطة دخول الصفحة.
- `app/almadina-app.tsx`: إدارة الجلسة، الحسابات، الإشعارات، وماسح الكاميرا.
- `app/components/`: جميع صفحات وواجهات العميل والإدارة.
- `app/lib/data.ts`: حساب المسؤول، عزل بيانات الحسابات، الحالات، المحافظات ورسوم التوصيل.
- `app/lib/palestine-locations.generated.ts`: دليل المناطق الرسمي الثابت الذي يولّده السكربت دون اتصال وقت التشغيل.
- `app/lib/server-database.ts`: واجهات الخادم وتسجيل الدخول وتشفير كلمات المرور ومزامنة البيانات المشتركة.
- `db/schema.ts` و`drizzle/`: جداول قاعدة D1 وملفات ترحيل البيانات.
- `worker/index.ts`: تشغيل الموقع وواجهات الحسابات المشتركة على Cloudflare Workers.
- `worker/render.ts`: تشغيل الموقع وواجهات الحسابات على Render/Node.
- `app/lib/postgres-d1-adapter.ts`: ربط منطق قاعدة البيانات نفسه بقاعدة PostgreSQL في Render.
- `render.yaml`: إنشاء خدمة Render وقاعدة PostgreSQL وربط متغيراتها تلقائيًا.
- `app/globals.css`: التصميم والألوان والحركات والاستجابة للجوال.
- `public/almadina-mark.svg`: أيقونة المدينة إكسبرس.
- `package.json`: أوامر التشغيل ومكتبات المشروع.

## حلول المشاكل الشائعة

- إذا ظهر `npm is not recognized`: ثبّت Node.js ثم أغلق VS Code وافتحه مجددًا.
- إذا ظهر خطأ متعلق بإصدار Node.js: شغّل `node -v` وتأكد أن الإصدار 22 أو أحدث.
- إذا لم يفتح الرابط: تأكد أن أمر `npm run dev` ما زال يعمل، وافتح الرابط المعروض فعليًا في الطرفية.
- إذا كان المنفذ 5173 مستخدمًا، سيختار Vite منفذًا آخر ويعرض الرابط الصحيح.
- إذا أردت فتح الموقع من الهاتف على نفس شبكة Wi‑Fi، استخدم رابط **Network** الذي يظهر في الطرفية.
- إذا أنشأت حسابًا ولم يظهر على جهاز آخر، تأكد أن الجهازين يفتحان عنوان الموقع أو الخادم نفسه، وليس نسختين منفصلتين من `localhost`.
- صلاحية الكاميرا تتطلب `localhost` أو اتصال HTTPS. إذا رفض المتصفح الإذن، استخدم إدخال رقم التتبع يدويًا.
