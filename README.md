# المدينة إكسبرس | Almadina Express

مشروع موقع عربي كامل لإدارة الشحن والتوصيل داخل فلسطين. صُمم استنادًا إلى الفيديوهات المرجعية، ويعمل على الهاتف والكمبيوتر مع واجهة عربية من اليمين إلى اليسار.

## تشغيل المشروع في VS Code

1. ثبّت **Node.js الإصدار 22 أو أحدث** من: https://nodejs.org/
2. فك ضغط المشروع في مجلد عادي؛ لا تشغّله وهو داخل الملف المضغوط.
3. افتح المجلد الكامل في VS Code باستخدام **File → Open Folder**.
4. افتح الطرفية باستخدام **Terminal → New Terminal**.
5. نفّذ الأمر التالي مرة واحدة لتثبيت المكتبات:

   ```bash
   npm install
   ```

6. بعد انتهاء التثبيت، شغّل الموقع:

   ```bash
   npm run dev
   ```

7. افتح الرابط الذي يظهر في الطرفية، وغالبًا يكون:

   ```text
   http://localhost:5173
   ```

يمكن كذلك تشغيل `RUN-WINDOWS.bat` على Windows أو `RUN-MAC.command` على macOS. هذه الملفات تثبّت المكتبات تلقائيًا عند التشغيل للمرة الأولى.

> لا يحتاج المشروع إلى Supabase أو Firebase أو ملف `.env` أو مفاتيح API لتشغيل النسخة المحلية. تُنشأ قاعدة بيانات Cloudflare D1 المحلية تلقائيًا عند أول تسجيل دخول أو إنشاء حساب.

## الرفع من VS Code إلى GitHub ثم Render

المشروع جاهز للنشر على Render من خلال الملف `render.yaml`. ينشئ هذا الملف خدمة الموقع وقاعدة PostgreSQL ويربطهما تلقائيًا، لذلك لا تكتب `DATABASE_URL` يدويًا ولا ترفعه إلى GitHub.

### 1. رفع المشروع إلى GitHub

1. أنشئ مستودعًا جديدًا وفارغًا في [GitHub](https://github.com/new) ولا تضف README أو `.gitignore` من GitHub.
2. انسخ رابط المستودع الذي ينتهي بـ `.git`.
3. افتح مجلد المشروع الكامل في VS Code، ثم افتح **Terminal → New Terminal** ونفّذ:

   ```bash
   git init
   git add .
   git commit -m "Deploy Almadina Express"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPOSITORY.git
   git push -u origin main
   ```

4. استبدل `USERNAME/REPOSITORY` باسم حسابك ومستودعك. إذا ظهر أن `origin` موجود مسبقًا، نفّذ بدل أمر الإضافة:

   ```bash
   git remote set-url origin https://github.com/USERNAME/REPOSITORY.git
   git push -u origin main
   ```

قد يفتح GitHub نافذة المتصفح لتسجيل الدخول عند أول `push`. لا تضع كلمة مرور GitHub أو أي مفتاح داخل ملفات المشروع.

### 2. نشر المستودع على Render

1. سجّل الدخول إلى [Render](https://dashboard.render.com/) بواسطة GitHub.
2. اختر **New + → Blueprint** ثم اربط مستودع المشروع.
3. سيتعرّف Render تلقائيًا على `render.yaml` ويعرض خدمتين: `almadina-express` و`almadina-express-db`.
4. اضغط **Apply** وانتظر حتى تنتهي حالة النشر إلى **Live**.
5. افتح رابط `onrender.com` الذي يظهر في صفحة خدمة `almadina-express`.

بعد أي تعديل لاحق من VS Code استخدم:

```bash
git add -A
git commit -m "Update website"
git push
```

سيبدأ Render نشر النسخة الجديدة تلقائيًا بعد وصول التعديل إلى فرع `main`.

> إعداد Render المرفق يستخدم الخطة المجانية للتجربة. خدمة الويب المجانية قد تتوقف مؤقتًا عند عدم الاستخدام، وقاعدة PostgreSQL المجانية تنتهي بعد 30 يومًا. للحفاظ على الحسابات والطرود بصورة دائمة، رقِّ قاعدة البيانات إلى خطة مدفوعة قبل انتهاء المدة؛ لا يحتاج الموقع إلى تعديل برمجي عند الترقية.

## حساب المسؤول

- البريد الإلكتروني: `admin@almadinaexpress.com`
- كلمة المرور: `Admin@123`

لا يحتوي المشروع على مستخدمين أو طرود أو مستلمين تجريبيين. أنشئ حساب عميل جديد من شاشة التسجيل، أو أضف المستخدمين والمندوبين يدويًا من لوحة المسؤول. يجب أن يكون رقم الجوال الفلسطيني مكوّنًا من 10 أرقام ويبدأ بـ `05`.

كل مستخدم يشاهد حسابه وطروده ومستلميه وفواتير تحصيله وإشعاراته فقط. لتبديل الحساب يجب تسجيل الخروج ثم إدخال البريد الإلكتروني وكلمة المرور للحساب الآخر. يحتفظ المسؤول بصلاحية إدارة جميع المستخدمين والطلبات، ويُعامل كل حساب «مندوب توصيل» ينشئه المسؤول كحساب موظف بصلاحيات تشغيلية مستقلة.

## الصفحات والخصائص

- تسجيل الدخول، إنشاء حساب جديد، زر للحسابات المتاحة التي سبق استخدامها على الجهاز يظهر في الشاشات الصغيرة فقط، تبديل الحسابات بإعادة إدخال كلمة المرور، وتتبع الطرود دون تسجيل الدخول بسجل زمني آمن.
- حسابات وطلبات محفوظة في قاعدة بيانات مشتركة، مع إمكانية تسجيل الدخول إلى الحساب نفسه من أي جهاز يفتح رابط الموقع نفسه.
- ماسح كاميرا لرموز QR والباركود في المتصفحات التي تدعم `BarcodeDetector`، مع إدخال رقم التتبع يدويًا.
- واجهة موظف مستقلة لحسابات المندوبين: يمسح الموظف كود الطرد بالكاميرا، ولا يقبل الخادم إلا نقل الحالة من «جاهز للإرسال» إلى «مشحون». يُسند الطرد إلى الموظف، ويُحفظ اسمه ووقت المسح في سجل التتبع، ويصل إشعار إلى صاحب الطرد.
- يعرض حساب الموظف الطرود التي استلمها فقط وتعليمات المندوب المكتوبة عند إنشاء الطرد، ولا يكشف فواتير التجار أو الملاحظة الخاصة بالمسؤول. ولا يستطيع حساب المستخدم العادي أو المسؤول استدعاء صلاحية شحن الطرد بالمسح بدل المندوب.
- لوحة العميل وإحصاءات الرصيد وحالات الطرود والتحديثات.
- إنشاء طرد، كتابة المحافظة والمدينة أو المنطقة بحرية، احتساب رسوم التوصيل تلقائيًا، وحفظ المستلمين المفضلين؛ يبدأ كل طرد جديد بحالة «قيد الإنشاء» ثم تُفتح رحلة تتبعه مباشرة. تظهر «التعليمات» للمندوب المسند فقط، بينما تظهر «الملاحظة الخاصة» للمسؤول فقط.
- سجل تتبع دائم من الأحدث إلى الأقدم يوضح وقت كل تحديث وموقعه وحالته وملاحظته، ويضيف حدثًا جديدًا عند تغيير الحالة بدل حذف السجل السابق.
- ملاحظات مرتبطة بحالات الطرد: يستطيع المستخدم صاحب الطرد والمسؤول إضافة ملاحظة للحالة الحالية، ويستطيع المسؤول كتابة ملاحظة اختيارية عند اعتماد أي حالة جديدة؛ يُحفظ اسم الكاتب والوقت ولا تظهر الملاحظات الخاصة في التتبع العام دون تسجيل.
- الطرود والرواجع والتحصيلات والإشعارات والبحث والمحذوفات.
- تنزيل تقارير CSV وExcel، واستيراد عدة طرود باستخدام ملف CSV قابل للفتح في Excel.
- صفحة تحصيلات تعرض المبالغ المتاحة وقيد التجهيز والجاهزة والمشحونة، وتنشئ فواتير من الطرود الواصلة والرواجع دون تكرارها.
- تفاصيل لكل فاتورة تشمل صافي التحصيل، رسوم التوصيل، توزيع الطرود حسب المنطقة، الاستثناءات، التنزيل والطباعة، ورمز تحقق لمستلم مفوض.
- لوحة إدارة للتجار والمندوبين والطرود والتحصيلات، تغيير حالات الطرود، تجهيز فواتير التحصيل، وإضافة حسابات الموظفين/المندوبين وحذفها.
- بيانات الاسم والجوال والمتجر أو المنطقة والبريد للعرض فقط داخل حساب المستخدم والمندوب؛ تعديلها متاح للمسؤول وحده من لوحة الإدارة، ومحمِي كذلك من جهة الخادم.
- تغيير نوع حساب التاجر يدويًا بين «عادي» و«بريميوم» من تبويب المستخدمين في لوحة المسؤول.
- أسعار التوصيل للحساب العادي: جميع مناطق الضفة 25 شيكل، القدس 35 شيكل، والداخل 80 شيكل.
- أسعار التوصيل لحساب بريميوم: جميع مناطق الضفة 20 شيكل، القدس 30 شيكل، والداخل 65 شيكل؛ تُطبّق تلقائيًا على إنشاء الطرود واستيرادها بعد تغيير نوع الحساب من لوحة المسؤول.
- تُضاف رسوم حجم قدرها 7 شيكل مرة واحدة فقط عندما يتجاوز أي من الطول أو العرض أو الارتفاع 40 سم؛ لا تُضاف عند 40 سم بالضبط، وتشملها فواتير التحصيل والاستيراد من CSV.
- الإعدادات، الملف الشخصي، رمز قفل محلي، تفضيلات الإشعارات، الوضع الفاتح والداكن، مركز المساعدة، وسياسة الخصوصية.
- تصميم متجاوب لجميع الشاشات، انتقالات، قوائم جانبية، تفاصيل فواتير ورمز تحقق متكيفان، وشريط تنقل سفلي للجوال والكمبيوتر.
- استيراد Excel من الشريط العلوي في نسخة الكمبيوتر فقط، دون ظهوره في قائمة الهاتف الجانبية.
- طباعة ملصقات جميع طرود المستخدم دفعة واحدة من شاشة الطرود على الشاشات الكبيرة فقط، مع تخصيص صفحة طباعة لكل طرد.

## حفظ البيانات

تُحفظ الحسابات والطلبات والمستلمون وفواتير التحصيل والإعدادات في قاعدة بيانات مشتركة على الخادم: **Cloudflare D1** في تشغيل Cloudflare أو **PostgreSQL** عند النشر على Render. لا تُحفظ كلمات المرور أو بيانات الطرود في `localStorage`؛ تُحفظ فقط بيانات تعريف غير حساسة للحسابات التي سبق استخدامها على الجهاز لتكوين قائمة «الحسابات المتاحة». تُشفّر كلمات المرور باستخدام PBKDF2، وتُحفظ جلسات تسجيل الدخول في ملفات تعريف ارتباط `HttpOnly` منفصلة لكل جهاز. يحسب الخادم قيمة كل فاتورة من الطرود الفعلية ويحمي حالتها وأرقامها من التعديل في المتصفح، ويتحقق من كود التحصيل وصلاحية الموظف على الخادم قبل اعتماد حالة «مشحون».

يمكن إنشاء الحساب من الهاتف ثم فتح رابط الموقع نفسه من الكمبيوتر أو أي هاتف آخر وتسجيل الدخول بالبريد الإلكتروني وكلمة المرور نفسيهما. تتم مزامنة الطلبات وتغييرات الحساب تلقائيًا بين الأجهزة، ويشاهد كل مستخدم بياناته الخاصة فقط، بينما يشاهد المسؤول جميع الحسابات والطلبات.

عند تشغيل `npm run dev` تُحفظ قاعدة البيانات المحلية داخل مجلد `.wrangler` على جهاز تشغيل الخادم. لفتح الموقع من هاتف آخر على شبكة Wi‑Fi نفسها استخدم عنوان **Network** الظاهر في الطرفية، مع إبقاء الخادم يعمل. للوصول من أي مكان خارج الشبكة المحلية، انشر الموقع على Render وفق الخطوات أعلاه أو على Cloudflare Workers/Sites؛ لا يكفي فتح `localhost` على كل جهاز على حدة.

تعريف قاعدة البيانات موجود في `.openai/hosting.json` تحت `"d1": "DB"`، وملفات إنشاء الجداول موجودة داخل مجلد `drizzle`.

## الملفات المهمة

- `app/page.tsx`: نقطة دخول الصفحة.
- `app/almadina-app.tsx`: إدارة الجلسة، الحسابات، الإشعارات، وماسح الكاميرا.
- `app/components/`: جميع صفحات وواجهات العميل والإدارة.
- `app/lib/data.ts`: حساب المسؤول، عزل بيانات الحسابات، الحالات، المحافظات ورسوم التوصيل.
- `app/lib/server-database.ts`: واجهات الخادم وتسجيل الدخول وتشفير كلمات المرور ومزامنة البيانات المشتركة.
- `db/schema.ts` و`drizzle/`: جداول قاعدة D1 وملفات ترحيل البيانات.
- `worker/index.ts`: تشغيل الموقع وواجهات الحسابات المشتركة على Cloudflare Workers.
- `worker/render.ts`: تشغيل الموقع وواجهات الحسابات على Render/Node.
- `app/lib/postgres-d1-adapter.ts`: ربط منطق قاعدة البيانات نفسه بقاعدة PostgreSQL في Render.
- `render.yaml`: إنشاء خدمة Render وقاعدة PostgreSQL وربط متغيراتها تلقائيًا.
- `app/globals.css`: التصميم والألوان والحركات والاستجابة للجوال.
- `public/almadina-mark.svg`: أيقونة المدينة إكسبرس.
- `package.json`: أوامر التشغيل ومكتبات المشروع.

## حلول المشاكل الشائعة

- إذا ظهر `npm is not recognized`: ثبّت Node.js ثم أغلق VS Code وافتحه مجددًا.
- إذا ظهر خطأ متعلق بإصدار Node.js: شغّل `node -v` وتأكد أن الإصدار 22 أو أحدث.
- إذا لم يفتح الرابط: تأكد أن أمر `npm run dev` ما زال يعمل، وافتح الرابط المعروض فعليًا في الطرفية.
- إذا كان المنفذ 5173 مستخدمًا، سيختار Vite منفذًا آخر ويعرض الرابط الصحيح.
- إذا أردت فتح الموقع من الهاتف على نفس شبكة Wi‑Fi، استخدم رابط **Network** الذي يظهر في الطرفية.
- إذا أنشأت حسابًا ولم يظهر على جهاز آخر، تأكد أن الجهازين يفتحان عنوان الموقع أو الخادم نفسه، وليس نسختين منفصلتين من `localhost`.
- صلاحية الكاميرا تتطلب `localhost` أو اتصال HTTPS. إذا رفض المتصفح الإذن، استخدم إدخال رقم التتبع يدويًا.
