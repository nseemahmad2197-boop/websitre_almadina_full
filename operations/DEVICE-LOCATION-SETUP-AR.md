# المنطقة التقريبية للجلسات على Render

يعمل عرض نوع الجهاز والطراز وإصدار النظام والتطبيق وتسمية الجهاز فور تحديث الموقع والتطبيقين. تسمية الجهاز يكتبها المستخدم؛ ليست إثباتًا لاسم الشخص الحقيقي أو مالك الهاتف. التطبيق لا يقرأ جهات الاتصال أو حساب Apple/Google لهذا الغرض.

المنطقة مصدرها عنوان الشبكة عند بوابة موثوقة. هي تقريبية وقد تتغير دقتها بسبب شبكة الهاتف أو VPN، ولا تستخدم GPS أو عنوان المستخدم المسجل. يحفظ الخادم أول منطقة موثوقة متاحة للجلسة مع وقت تحديدها، ويحتفظ بها حتى نهاية الجلسة. إذا لم تتوفر المعلومة يعرض «غير متاحة» بدل تخمين مدينة.

## لماذا تحتاج إعدادًا على Render؟

نسخة Render لا تثق بترويسات المدينة أو IP التي يرسلها أي عميل. لا يمكن إضافة مدينة موثوقة بمجرد تحديث الواجهة. المسار المدعوم هو Cloudflare Worker أمام Render يرسل معلومات `request.cf` إلى Render مع سر للخادم فقط. لا يرسل التطبيق عنوان IP إلى مزود تحديد موقع خارجي. النسخة المنشورة مباشرة كـ Cloudflare Worker تستفيد من `request.cf` دون بوابة إضافية.

## إعداد البوابة بعد مراجعة النطاق

1. اختر نطاقًا مملوكًا لك ليكون عنوان الموقع وواجهة API، مثل `https://app.example.com`. أبقِ خدمة Render وقاعدة البيانات الحالية كما هما. الملف `secure-ingress-worker.mjs` نموذج جاهز للبوابة؛ لا ترفعه كتطبيق بديل للموقع.
2. أنشئ Worker مستقلًا في Cloudflare من هذا الملف. اضبط `RENDER_ORIGIN` بعنوان Render الحالي كاملًا مثل `https://your-service.onrender.com`، و`PUBLIC_ORIGIN` بالنطاق المختار. اربط النطاق بالـ Worker.
3. أنشئ سرًا عشوائيًا بطول 32 حرفًا على الأقل، مثل ناتج `openssl rand -hex 32`. احفظه باسم `EDGE_TOKEN` في **Secrets** للـ Worker. لا تضعه في المستودع أو التطبيقات أو الصور المرسلة.
4. اختبر مسار البوابة وحدث عناوين API في تطبيقي Android وiOS إلى النطاق المختار قبل إلزام جميع الطلبات بالبوابة. نقل النطاق يستلزم تسجيل دخول جديد لأن ملفات تعريف الارتباط والبصمات المسجلة ترتبط بالنطاق؛ سجّل المفاتيح الحيوية مجددًا عند الحاجة.
5. في نافذة انتقال مخططة، اضبط في Render `ALMADINA_EDGE_TOKEN` إلى السر نفسه، و`ALMADINA_PUBLIC_ORIGIN` إلى `PUBLIC_ORIGIN` نفسه، ثم أعد نشر الخدمة. بعد ذلك الطلبات المباشرة القديمة إلى API على `onrender.com` تُرفض؛ لذلك يجب وصول المستخدمين إلى النسخ التي تستخدم النطاق الجديد. لا تفعّل الإلزام بينما ما زالت نسخ قديمة تعتمد عنوان Render.
6. اختبر تسجيل الدخول والخروج وإنشاء متابعة ورفع صوت وطلبات المتصفح والبصمة من النطاق الجديد. سجّل دخولًا جديدًا من الهاتف وافتح «الأجهزة المرتبطة» لتظهر المنطقة إن وفرتها Cloudflare. لا تختبر أو تضبط ذلك بحسابات مستخدمين حقيقيين دون موافقتهم.

يمكن الرجوع عن إلزام البوابة بحذف `ALMADINA_EDGE_TOKEN` و`ALMADINA_PUBLIC_ORIGIN` من Render ثم إعادة النشر. بيانات الجلسات السابقة لا تُحذف، لكن نطاق ملفات الدخول يتطلب إعادة تسجيل الدخول بحسب العنوان المستخدم.

## ضمانات التنفيذ

- البوابة تستبدل معلومات IP والمنطقة ولا تمرر قيم العميل المزورة.
- يرفض Render السر الخطأ قبل استدعاء قاعدة البيانات، ويتجاهل معلومات الموقع بلا سر.
- عنوان Render الهدف ثابت، HTTPS فقط؛ لا تُتبع التحويلات تلقائيًا مع السر.
- تُحذف بيانات الجهاز والمنطقة عند حذف الجلسة أو إلغائها أو إغلاق الحساب. تدوير الجلسة عند تغيير كلمة المرور يحافظ على تسمية الجهاز الحالي.
- هذا التحديث يجهّز الربط؛ لم ينشر البوابة أو يغير إعدادات Render أو عناوين التطبيقات تلقائيًا.
